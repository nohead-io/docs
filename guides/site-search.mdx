---
title: Site search
description: Search published records straight from your site's browser with a search token, or add InstantSearch.
---

A **search token** lets your site search published records straight from the browser, without going through the API: results come back as fast as you type, and the searches don't count toward your API requests. Search runs on [Meilisearch](https://www.meilisearch.com), so its clients and [InstantSearch](https://www.algolia.com/doc/guides/building-search-ui/what-is-instantsearch/js/) work as they are.

## Create a token

In the web app, open your project's **Search tokens** page, choose **New search token**, name it and pick its collections. The token shows with what your site needs: the search URL, the token, and each collection's index. **How to use** on the list shows them again.

A token finds only the **published** records of the collections it names. The search engine enforces that: other collections, other projects and unpublished records stay out of reach, whatever a request asks for.

<Warning>
A token is public: it goes in your page source. Every field of the published records it finds can be read with it, so leave out collections your site keeps behind its own sign-in, or that hold fields you don't publish.
</Warning>

## Search from a site

```javascript
const response = await fetch(`${searchUrl}/multi-search`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${token}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    queries: [{ indexUid: index, q: "lentil", limit: 10 }],
  }),
})
const { results } = await response.json()
for (const hit of results[0].hits) console.log(hit.data.title)
```

Hits look like records:

- `id` (`rec_…`), `status`, and `published_at`, `created_at` and `updated_at` as Unix seconds
- field values under `data`, by field key: rich text as plain text, JSON as a string

Several collections at once take one query each, or a federated search across them (`federation: {}` in the request).

## Filter and sort

Fields take part in searches by their [search settings](/guides/content-modelling): words match `searchable` fields, and `filterable` and `sortable` fields can be used in filters and sorts. Name them under `data`:

```javascript
{ indexUid: index, q: "soup", filter: 'data.cuisine = "french"', sort: ["published_at:desc"] }
```

## InstantSearch

```javascript
import instantsearch from "instantsearch.js"
import { searchBox, hits } from "instantsearch.js/es/widgets"
import { instantMeiliSearch } from "@meilisearch/instant-meilisearch"

const { searchClient } = instantMeiliSearch(searchUrl, token)

instantsearch({ indexName: index, searchClient })
  .addWidgets([
    searchBox({ container: "#search" }),
    hits({ container: "#hits", templates: { item: (hit, { html }) => html`${hit.data.title}` } }),
  ])
  .start()
```

## Revoke a token

Delete it on the **Search tokens** page: searches with it fail at once, and your other tokens keep working. A token's collections are fixed, so searching another collection means a new token. While a project or organization is scheduled for deletion its tokens stop working, and they work again if it is restored.

Your servers can also search through the API with an API key: `GET /v1/collections/{collection_id}/search` and `GET /v1/projects/{project_id}/search` return full records, with `expand`.
