Every image you upload has an `image_url`: the whole image, served from a CDN. Image URLs are open, so you make any size, crop or format of an image by writing [imgproxy](https://docs.imgproxy.net/usage/processing) processing options into its URL. There is no API call per rendition, and frameworks' image components can build their `srcset` themselves.

## Image URLs

An asset that is a ready JPEG, PNG, GIF, WebP or AVIF image has an `image_url` (it is `null` for other files):

```text
https://images.nohead.io/plain/<project>/<asset>
```

Write processing options before `/plain/`, and a format after `@`:

```text
https://images.nohead.io/rs:fill:1200:630/g:sm/plain/<project>/<asset>@webp
```

That is a 1200×630 crop, around the most interesting part of the image, as WebP. Assets also have a `preview_url`, a small WebP that fits in 640×640, for thumbnails.

## Common options

| Option | Example | What it does |
|---|---|---|
| `rs:<fit>:<width>:<height>` | `rs:fit:800:0` | Resize. `fit` keeps the whole image inside the box, `fill` fills it and crops, `force` stretches. `0` leaves a side free. |
| `g:<gravity>` | `g:sm`, `g:fp:0.5:0.3` | What a crop keeps: `sm` the most interesting part, `fp:x:y` a focal point, `ce`, `no`, `so`, `ea`, `we` a side. |
| `dpr:<n>` | `dpr:2` | Pixel density, for 2x screens. |
| `q:<n>` | `q:75` | Quality, 1 to 100. |
| `@<format>` | `@avif` | The format: `webp`, `avif`, `jpeg` or `png`. |
| `bl:<n>`, `sh:<n>`, `pix:<n>` | `bl:10` | Blur, sharpen, pixelate. |

Options combine in any order: `rs:fill:400:400/g:sm/dpr:2/q:80`. imgproxy's [processing options](https://docs.imgproxy.net/usage/processing) list them all.

## Frameworks

Image components take a loader that turns a source and a width into a URL. `@nohead/sdk/images` has one for each, with no dependencies; it leaves other images, the site's own, as they are:

- **Next.js:** in a file named by `images.loaderFile` in next.config, `export { nextImageLoader as default } from "@nohead/sdk/images"`. Then `<Image src={asset.image_url} width={1200} height={630} alt={asset.alt} />` gets a `srcset` of renditions.
- **Astro:** in a module named by `image.service.entrypoint` in astro.config, `export { astroImageService as default } from "@nohead/sdk/images"`.
- **Nuxt Image:** in a provider file in nuxt.config's `image.providers`, `export { nuxtImageProvider as default } from "@nohead/sdk/images"` (on Nuxt Image 1, `export { getImage } from "@nohead/sdk/images"`).

In your own code, `imageUrl(asset, { width: 800, fit: "cover", format: "webp" })` writes the options into an asset's URL; Python has `nohead.images.image_url` and Ruby `Nohead::Images.url` ([SDKs](/guides/sdks#upload-files)). Without the SDK, a loader only has to add the options before `/plain/`:

```javascript
// Next.js, by hand: a file named by images.loaderFile in next.config
export default function noheadLoader({ src, width, quality }) {
  const options = [`rs:fit:${width}:0`, quality && `q:${quality}`].filter(Boolean)
  return src.replace("/plain/", `/${options.join("/")}/plain/`)
}
```

There is no API call for renditions: write the options into the URL, in your code or your framework's loader.

## Limits

Uploaded files, images or not, are at most 10 MB each on Free and 100 MB on paid plans.

So that any URL stays cheap to serve:

- Renditions are at most 4096 pixels a side, and originals at most 50 megapixels.
- Options that would return a file as stored are refused: `raw`, `skip_processing` and `strip_metadata`. Renditions never carry a photo's metadata, such as its location.
- SVG images have no `image_url`, only a `preview_url` (a WebP): their `file_url` downloads them as they are.
- Each rendition is cached for a year. Requests from one address are rate limited, generously enough for pages full of images.

## Video, audio and other files

Every asset also has a `file_url` once its upload completes, which downloads the file as you uploaded it under its filename, and video and audio have a `media_url`, which plays it in the browser (it is `null` for other files). Both are open URLs on a CDN, like image URLs, and never expire:

```jsx
{asset.media_url && asset.content_type.startsWith("video/") && (
  <video src={asset.media_url} controls preload="metadata" playsInline />
)}
{asset.media_url && asset.content_type.startsWith("audio/") && (
  <audio src={asset.media_url} controls />
)}
<a href={asset.file_url}>Download {asset.filename}</a>
```

- Video and audio play as uploaded, with seeking. MP4, QuickTime, M4A, 3GP, WebM, Matroska, MP3, AAC, FLAC, WAV and Ogg files get a `media_url`; other types only download. Browsers play MP4 (H.264 with AAC audio), WebM, MP3, AAC and WAV everywhere, so prefer those. Each file must fit your plan's upload limit.
- A file uploaded as one of those types must be one: completing an upload whose content doesn't match its declared type fails, as it does for images.

## Where an asset is used

Before you delete or replace an image or file, check which records use it:

```bash
curl "$NOHEAD_API_URL/v1/assets/ast_01J9ZQ3F8X/usage" \
  -H "Authorization: Bearer $NOHEAD_API_KEY"
```

It counts the records that use the asset in an asset field or as an image in a rich text field, in their content or in their pending draft, since merging the draft needs the asset. Deleted records, fields and collections don't count, and neither does history. The response has:

- `records`: how many records use it.
- `published`: how many of them are published with it in their content, which is what your sites show.
- `uses`: the 10 most recently updated of them, each with its `record` and the keys of the `fields` that use the asset.

It needs `records:read` as well as `assets:read`, and published-only keys get `403`. In the SDKs, it is `assets.usage`.

In the web app, open an asset on the **Assets** page: **Used in** lists the records that use it. Deleting an asset that records use asks first.

## Deleted and purged assets

Knowing an asset's URL is all it takes to see it, as with any public image or file. A deleted asset's URLs keep working until it is purged (30 days later, or sooner with `POST /v1/assets/{asset_id}/purge`). A purge removes its file, media and every rendition from the CDN within a minute or so; browsers keep what they cached.
