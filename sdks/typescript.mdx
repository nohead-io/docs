```bash
npm install @nohead/sdk
```

The package is ESM; Node 22+ can also `require()` it. It runs on Node 22, 24 and 26, Bun, Deno, Cloudflare Workers and other runtimes with `fetch` and Web Crypto. Use it on servers: API keys are secrets. The [overview](/sdks/overview) covers reading and writing, retries, errors, uploads and webhooks, with examples in every language.

## Configure the client

```ts
import { Nohead } from "@nohead/sdk"

const nohead = new Nohead({
  apiKey: process.env.NOHEAD_API_KEY, // the default
  timeout: 10_000, // milliseconds per attempt
  maxRetries: 3,
})
```

| Option | Default | |
|---|---|---|
| `apiKey` | `NOHEAD_API_KEY` | A project [API key](/guides/api-keys). Required. |
| `projectId` | the key's project | Looked up once with `GET /v1/me` when omitted. |
| `maxRetries` | `2` | See [retries](/sdks/overview#retries-and-idempotency). |
| `timeout` | `60000` | Milliseconds per attempt. |
| `fetch` | `globalThis.fetch` | For proxies, instrumentation and tests. |
| `headers` | `{}` | Added to every request. |
| `warnings` | `true` | Logs deprecation and plan usage warnings, once each. |
| `onRetry` | | Called before each retry, with its attempt, delay, URL, status and error. |

API keys belong to a project, so methods like `collections.list()` need no project ID, and collections can be named by ID or slug.

## Typed record data

Describe a collection's fields and pass the type, and a record's `data` is typed:

```ts
interface Post {
  title: string
  author: string
}

const post = await nohead.records.get<Post>(id) // post.data.title: string
await nohead.records.update<Post>(id, { data: { title: "Hello again" } })
```

The type is a promise you make; nothing is checked at runtime. The record type itself is `Nohead.Record<Post>`, also exported as `NoheadRecord`. Field names stay as the API sends them (`published_at`, `data`), so the [API reference](/api-reference/overview) applies as it is.

## Raw responses

`withResponse()` gives the HTTP response with the result, for its headers:

```ts
const { data, response, requestId } = await nohead.records.get(id).withResponse()
console.log(data.id, requestId, response.headers.get("RateLimit-Remaining"))
```

## Images in frameworks

`@nohead/sdk/images` builds image URLs (`imageUrl`) and has loaders for Next.js and Nuxt Image, and `@nohead/sdk/astro/image-service` is an image service for Astro, with no dependencies: see [Images](/guides/images#frameworks).

## Astro content collections

`@nohead/sdk/astro` loads collections into Astro's content collections (Astro 5.9 or later), so pages read them with `getCollection`, `getEntry`, `reference()` and `render()`. Each published record becomes an entry whose `id` is the record ID and whose `data` is its fields, when the site builds and when `astro dev` starts:

```ts
// src/content.config.ts
import { defineCollection, reference } from "astro:content"
import { z } from "astro/zod"
import { noheadLoader } from "@nohead/sdk/astro"

// Astro reads .env into import.meta.env, not process.env.
const apiKey = import.meta.env.NOHEAD_API_KEY

export const collections = {
  people: defineCollection({
    loader: noheadLoader({ collection: "people", apiKey }),
    schema: z.object({ name: z.string(), slug: z.string() }),
  }),
  posts: defineCollection({
    loader: noheadLoader({ collection: "posts", expand: ["cover"], body: "body", apiKey }),
    schema: z.object({
      title: z.string(),
      slug: z.string(),
      date: z.coerce.date(),
      authors: z.array(reference("people")),
      cover: z
        .object({
          image_url: z.string(),
          width: z.number(),
          height: z.number(),
          alt: z.string().optional(),
        })
        .optional(),
    }),
  }),
}
```

- **Rich text** reads as HTML, for `<Fragment set:html={post.data.summary} />`. `body` names one rich text field that moves out of `data` for `render(entry)` to render as `<Content />`. With `richText: "markdown"`, rich text reads as Markdown and that field goes through Astro's own Markdown pipeline (your plugins, syntax highlighting, headings).
- **Assets** named in `expand` replace their ID with the asset: its `image_url`, `width`, `height`, `alt` and the rest, ready for `<Image>` with the [image service](/guides/images#frameworks).
- **Relations** stay record IDs, for `reference()` and `getEntry`.
- **Empty fields** are left out of `data`, so `.optional()` fits them. Dates are strings: `z.coerce.date()` makes them `Date`s.
- **Order:** Astro keeps no order for a collection, so sort entries in the page: `posts.sort((a, b) => b.data.date.valueOf() - a.data.date.valueOf())`.
- **Published records** are the only ones that load, so a published-only key is enough. `filter` adds conditions, such as `{ featured: true }`.

The [README](https://github.com/nohead-io/nohead-typescript#astro) has a page that renders an entry and the loader's other options.

## Methods

Every method follows a resource of the API: `records`, `drafts`, `collections`, `fields`, `migrations`, `assets`, `webhooks`, `search`, `auditEvents` and more. Each endpoint in the [API reference](/api-reference/overview) shows its call in TypeScript, and the [README](https://github.com/nohead-io/nohead-typescript#reference) lists them by resource.
